# 顧客管理サンプル

ブラウザーで `app/index.html` を開くと、検索→閲覧→変更・削除を操作できます。外部サーバー、通信、DBは使いません。データはメモリ上の1件で、リセット/再読込で初期化します。

画面右上の権限を変更すると閲覧専用の動作を試せます。保存/削除の失敗を選択して再試行できます。削除した顧客は検索しても復活しません。

この参考アプリは仕様の読み方を学ぶためのものです。CLIがアプリのDOMを操作するテストや、モデルとアプリの自動適合検証は初版に含みません。氏名等の実データはモデルではvalid/invalid、existsなどへ抽象化しています。

## 仕様書

リポジトリルートで:

```powershell
.\dist\ucspec.exe build --project examples/customer-crud/spec/project.json
Start-Process .\examples\customer-crud\artifacts\usecase-spec\index.html
```

共有モデルはspec/model/customer.json、目的はspec/usecases、独立したチェックはspec/checksです。検索→閲覧の遷移を全ユースケースで共用しています。

変更ユースケースは遷移9/9ですが、プライムパス7/8、8遷移以内の完了経路5/20です。すべてのパスを自動登録して100%とするサンプルにはしていません。閾値設定と残る経路の意味を確認してください。

## 学習用の変更

1. 保存失敗後にキャンセルするシナリオを追加し、どの指標が変わるか確認する。
2. `openEdit` のガードを意図的に弱め、閲覧専用ユーザーの回帰ケースが失敗することを確認する。
3. コピーした仕様で削除成功時のexists更新を誤ってtrueにし、独立した削除結果の検査で検出する。
4. limits.statesを小さくし、解析未完了が成功扱いにならないことを確認する。

変更前のreport.jsonをbaselineとして保存すると影響比較ができます。元のサンプルを破壊せず、initで作った別ディレクトリやGitブランチで試してください。
