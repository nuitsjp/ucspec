## 2026-10-12: 構造だけで書く状態定義への作り直し

状態定義の形式を作り直しました。要素と関係は [状態定義モデル](model.html) にまとめています。データの層（変数、条件式、イベントの入力、`set`、ガード、不変条件、決定表）をなくし、名前を識別子にしました。状態は入れ子で書き、イベントは状態の中に書いて遷移を兼ねます。ディシジョンはイベント・開始・分岐の中に書き、分岐は名前だけを持ちます。アクターを定義してイベントとユースケースから参照し、ファイルの最上位を名前のないルート状態として扱います。ユースケースは `starts`・`ends`（遷移の参照）・`scope`（イベントの参照）で範囲を定め、シナリオはイベント名と通る分岐名で書きます。網羅率から `conditions` と `multipleConditions` を外しました。名前の表記ゆれは、productionのCodecのNFKC正規化で検出します。

- サンプルとinitテンプレートを新しい形式で書き直しました。構造だけになったため、編集・削除のユースケースは顧客閲覧から始め、閲覧には0件の後に再検索するシナリオを加えました。実際のELKとスキーマ検査を含む生成で、4つの末端状態・18シナリオ（ユースケース11、回帰7）がverified、診断0件です。
- 旧形式に依存していたテストを削除し、コンパイラー、エンジン、解析、描画、スキーマのテストを新しい設計で書き直しました。go vet、全Goテスト（`-mod=readonly`を含む）、`go mod verify` が成功しました。
- ブラウザー検査の中身（`scripts/browser-smoke.js`）を新しいサンプルに合わせ、`scripts/test-browser.ps1` が生成した `smoke.js` をplaywright-cliで直接実行して14項目すべての合格を確認しました。この過程で、図の切り替えに使うキーをGoが `>` をエスケープして作るため、回帰シナリオの選択で図が見つからない不具合を見つけて修正しました。`scripts/test-browser.ps1` が `open` の後に止まっていた原因は、playwright-cliの `open` が起動するセッション常駐プロセスが呼び出し元の標準出力を引き継ぐため、パイプで受けると終端が来ないことでした（bashでも `| cat` で同様に止まり、常駐プロセスを終了させた時点で終わることを確認）。スクリプトは呼び出しごとに別ファイルへ出力し、共有を許して読み、CLIのプロセスだけを待つ形に直しました。修正後、スクリプト経由で14項目の合格を2回（各12秒）、CSPを壊したレポートが失敗することを確認し、いずれも常駐プロセスは残りませんでした。

## 初期ソース作成時の未実行・未確認

外部Goモジュールを取得するネットワークが利用できませんでした。`go mod download` はproxy.golang.orgの名前解決で失敗し、`go test ./...` は外部モジュールのgo.sumエントリーがない段階で停止しました。

そのため以下は未確認です。

- **本物のelk-go・Go JSON Schema・YAMLを結合した総合テストとCLIビルド**。
- **Windows実機での起動、実行中exeの自己置換、PowerShellスクリプト実行**。
- GitHub Actionsの実行、Releaseからの実ダウンロードと更新。
- 任意の大規模モデル、階層状態、実アプリとの自動適合テスト。

依存のAPIを前提に実装したアダプターとWindows用テストは同梱しています。依存をダウンロードできるWindows環境で `scripts/build.ps1` を実行し、問題があれば修正したうえで配布してください。

**このZIPには、動作確認済みの製品exeも、偽のELK代替版exeも含めていません。** go.sumの値を推測して生成することもしていません。初回のネットワーク利用可能環境で確定し、コミットします。

## 結果の読み方

[サンプル検査結果](verification/sample-report.json) は、実際のコア解析から生成したものです。表示用fixtureで置換した検査結果ではありません。

HTMLの単体試験だけは `testkit.FixtureLayout` に固定座標を与えています。これはGo製ELKの配置品質を検証したことにはなりません。productionのmainは必ずadapters.LayoutJSONを利用し、ELKの失敗時にfixtureへフォールバックしません。

初期ソース作成時は、GitHub接続に新規リポジトリ作成操作がなかったため、**GitHub上のリポジトリ作成・初回pushは未実施**でした。`scripts/publish-github.ps1` は利用者の認証済みGitHub CLIでこの操作を行うためのものです。

`verification/results.json` と `verification/sample-report.json` は作成時点の実測記録のため、旧リポジトリ名を含む参照を保持しています。現在の製品名と更新元は `ucspec` / `nuitsjp/ucspec` です。

## 再実行

コアのみ:

```powershell
.\scripts\test-core.ps1
```

実依存・Windowsを含む総合確認:

```powershell

```
