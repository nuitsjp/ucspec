# 網羅率と保証範囲

このツールが計算するのは登録された有効なシナリオの**定義網羅率**です。対象アプリのコードを実行したカバレッジではありません。

| JSON上の指標 | 分母 | 網羅済みとする条件 |
|---|---|---|
| states | usecase.startsからscope内の遷移で到達できる末端状態 | 有効なシナリオの開始時または遷移後に到達 |
| compositeStates | 上記の末端状態の親として有効になる複合状態 | 有効なシナリオでその親が有効になる |
| transitions | scope内の、完了シナリオに含められる外部・内部遷移 | 有効なシナリオに一度以上出現 |
| pairs | 連続した2遷移の成立可能な組み合わせ | 同じ順で連続して出現 |
| primePaths | 他の単純パスの真部分経路ではない単純パスのうち成立可能なもの | シナリオの連続した部分経路として出現 |
| boundedPaths | steps上限内で起点からendまで進む遷移ID列 | 完全なシナリオ列が一致 |
| conditions | 到達構成とイベント入力で現れる、各ガード内の名前付き原子条件の真偽 | 有効なシナリオのガード評価に同じ真偽が現れる |
| multipleConditions | 各ガードの名前付き原子条件について到達可能な真偽ベクトル | 同じ組み合わせが有効シナリオの評価に現れる |

`choices`は通常状態や複合状態ではないため、`states`/`compositeStates`の分母に入りません。choiceから出る分岐遷移は既存の遷移定義として扱い、`transitions`、`pairs`、`primePaths`、`boundedPaths`、`conditions`、`multipleConditions`の分母に含めます。`kind`が`internal`の遷移も通常の遷移IDとして同じ指標の分母に含め、状態を移動しない場合でもシナリオのstepと経路候補へ現れます。ユースケースの`scope`に各遷移IDを含めるかどうかが、目的別の遷移数と連続経路の分母へ反映されます。choiceへ入る遷移と分岐の選択は別々の内部の実行ステップです。

状態の`layoutLayer`は描画専用の配置順です。同じ親内で小さい値を上の配置帯に置き、同じ値の帯内の上下・横配置は自動にします。同じY座標や横一列は保証しません。未指定の状態とchoiceも自動配置です。`layoutLayer`、黒丸の位置、`DOWN`方向、横位置、間隔、矢印の配置は、実行グラフ、`scope`、各網羅率の分母・分子、解析完了状態を変えません。

プライムパスは末端状態と選択疑似状態を頂点とする単純パスから作り、有限データも含む実行グラフで成立性を検査します。内部遷移は同じ状態を始点・終点とする実行ステップとしてそのIDを経路へ含めます。複合状態を遷移先に指定した場合はinitialをたどった末端状態へ接続し、親状態の遷移は適用できる子状態からの接続として候補を作ります。最初の頂点に戻って閉じる閉路は許します。閉路の回転も別経路として扱います。無制限の反復回数のすべてを要求するものではありません。

部分状態への到達は親状態への到達にも数えますが、兄弟の部分状態は網羅済みにしません。一般例として、複合状態「申請」に子状態「下書き」と「確認待ち」がある場合、下書きだけを通るシナリオは申請と下書きを網羅しますが、確認待ちは未網羅です。親に定義した同一遷移は複数の子から実行できても、transitionsでは定義IDを一度だけ数えます。内部遷移も定義IDを一度だけ数え、状態を移動しない実行を含む経路として扱います。子ごとの適用は成立可能な連続遷移や経路の指標で確認します。描画用の開始記号・initialへの矢印は状態・遷移の網羅率に加算しません。

`transitions/pairs/primePaths` の候補を含む完了シナリオが有限実行グラフに存在しない場合は `infeasible` に記載します。完了できない分岐があること自体を無条件で正しいとは扱いません。各usecase開始点の完了可能性検査と、必要ならrecoverableなどの性質を併用してください。

## 境界と不完全な解析

`limits.states` は選択疑似状態の中間構成を含む実行グラフの構成数、`combinations` は単一イベントの入力組み合わせ数、`paths` は経路/成立性探索やイベント評価の作業量、`steps` はboundedPathsの最大遷移数です。探索上限到達は `complete:false` とします。

未完了の分母は確定値ではありません。%を表示しても合格判定には使いません。到達不能を証明できない候補を勝手に分母から除外しません。分母0は%なし（N/A）です。

boundedPathsは遷移ID列で重複をまとめます。同じ遷移列に異なるデータがある場合、それは条件系の指標で別に確認します。開始から終了しない有限prefixや無限実行の全網羅ではありません。

条件網羅はガード内の短絡評価とは別です。実際に評価する候補のガードでは、すべての名前付き条件の論理的真偽を計算します。外部・内部を問わず、階層状態の遷移選択では末端状態から親へ調べ、有効な候補がある最も内側の状態で止まります。その外側にある親のガードは実行時に評価しないため条件網羅にも加算しません。choiceでは選択疑似状態へ入る遷移の`set`を反映してから分岐のガードを評価し、成立した一つだけを実行します。重複成立や抜けは検証エラーで、暗黙のelseはありません。入力の真偽すべてを機械的に2^nで分母にする方式ではなく、有限モデルで到達可能な組み合わせが対象です。MC/DCは実装していません。

## シナリオと探索の独立性

シナリオが一つもなくてもscope/starts/endから検査対象を作ります。有効でないシナリオを分子に含めません。回帰ケースは定義網羅率へ加算せず、独立した合否として表示します。

シナリオの自動追加や期待結果の自動承認はありません。候補を追加する場合は名前・意図・入力・期待結果を確認します。

## 未網羅項目のレビュー方針

経路が違うことと、別の目的・期待結果を持つシナリオが必要なことは一致しません。顧客との接点を持つ開発者が、次の粒度で不足を評価します。これはレビューの指針であり、検査閾値を変更する規則ではありません。

| 指標 | 評価・管理する粒度 |
|---|---|
| states | 未到達の各末端状態を評価し、その利用状況や結果の不足を確認する |
| compositeStates | 未到達の各複合状態を評価する。親への到達と各子状態の通過は分けて確認する |
| transitions | 未網羅の各遷移を原則評価し、基本的な振る舞いの不足を確認する |
| conditions | 条件ごとの未網羅の真偽を原則評価する |
| multipleConditions | 成立可能な未網羅の組み合わせを評価する。同じ業務ルールで説明できるものはまとめる |
| pairs | 前の操作が次の操作の意味に影響する組み合わせを重点的に評価する |
| primePaths | 既存シナリオと異なる目的・期待結果・状態履歴を持つ経路を評価する |
| boundedPaths | 探索に使い、全経路の個別判定を必須にしない。反復や順序の違いに意味がある場合に管理する |

ユースケースの `coverageReviews` に、シナリオ追加が必要（addScenario）、既存シナリオで代表（represented）、禁止すべき振る舞い（forbidden）の判断と理由を記録します。複数の未網羅項目を一つの判断へまとめられます。現時点の評価がない項目は未評価のまま表示します。記法と変更後の再評価については記述ガイドの「未網羅項目の評価記録」を参照してください。

一度と二度の再試行を同じシナリオで代表させる場合、入力保持、回数によらない振る舞い、重複処理の防止など、代表させる前提を `architectureRequirements` に記録します。回数制限や回数に応じた待ち時間が仕様にあるなら、その境界には別の評価が必要です。前提の記録は設計・実装の適合を証明しません。

評価記録は分母・分子・閾値判定から独立しています。評価済みであっても未網羅の経路は未網羅として残ります。禁止する記録を追加しても、その経路をモデルから削除したことにはなりません。探索が未完了なら評価できた項目があっても全体を検証済みにしません。

## サンプルの読み方

顧客管理サンプルでは、`searchFound`と`searchEmpty`の内部遷移、`openCustomer`から`customerAvailability`へ入る遷移、そのchoiceから出る`openView`/`openGone`を、遷移・連続経路・条件系の対象とします。図の通常表示は外部・内部を問わず`defaultVisible`で制御しますが、表示対象を変えても網羅率の分母・分子は変わりません。シナリオ、未網羅候補、反例で選択した経路は属性に関係なく表示されるため、通常非表示のメニュー移動を含む経路も確認できます。

サンプルはtransitions/conditions/multipleConditionsのみ100%を要求します。したがって他の指標が100%未満でも全体statusはverifiedになります。すべての指標を100%と解釈しないでください。
