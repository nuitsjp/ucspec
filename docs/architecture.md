# アーキテクチャ

## 所有と依存方向

共通ツールは独立したGoモジュール/CLIです。各プロダクトは構造化仕様と使用版を所有します。コードはコピーせず実行ファイルを配布します。

```text
cmd/ucspec
  └─ app                 CLI・ファイル出力・終了コード
      ├─ compiler        JSON/YAML読込・形式検証・統合・参照解決
      ├─ engine          イベントの振り分け・ディシジョン・シナリオ再生
      ├─ analysis        制御グラフ・完了可能性・網羅率・差分
      ├─ report          レイアウト要求・SVG・HTML
      ├─ project         初期化・テンプレート配置
      └─ update          Release確認・検証・版固定更新

model                     外部ライブラリを知らない共通型
adapters                  YAML / JSON Schema / elk-goとの接続
assets                    embedされた仕様形式・ガイド・閲覧資産
```

mainだけがproductionのCodecとLayoutを組み立てます。coreテストではCodecにJSONを、reportの単体テストではレイアウト契約用fixtureを注入します。fixtureは製品機能のELK代替ではありません。productionで外部依存に失敗しても、黙って簡易レイアウトへ切り替えません。

## パイプライン

仕様読込 → schema検証 → 全ファイルのルート状態への統合 → 名前と参照の解決 → 共通内部モデル → 制御グラフの探索/シナリオ再生 → 検査結果 → elk-go配置 → SVG/HTML。Documentのルートにある`commonRules`は共通内部モデルの説明資産として保持し、HTMLの「共通ルール」へ表示します。

各ファイルの最上位は名前のないルート状態です。コンパイラーは全ファイルの最上位の`start`・`events`・`states`を一つのルート状態へ統合し、入れ子の状態をルートからのパスで識別する平らな表へ変換します。イベント・開始・分岐は、`状態:イベント`、`状態:[開始]`、`…>分岐`という遷移IDを持つ一つの遷移表へ、ディシジョンはそれを持つ遷移に属する無名の節点へ変換します。状態の参照は完全なパスまたは一意なパスの末尾で解決し、曖昧な参照はエラーにします。名前の表記ゆれは、productionのCodecが与えるNFKC正規化で兄弟間の衝突として検出します。

## 実行モデル

仕様はデータを持ちません。変数、条件式、ガード、イベントの入力はありません。実行の構成は、有効な末端状態一つか、解決中のディシジョン（とイベントを起こした末端状態）のどちらかです。末端状態の祖先はすべて有効です。並行領域、履歴状態、入場・退場アクションは対象外です。

- 振り分け: 末端状態で起こせるイベントは、末端状態からルート状態までの各状態に書かれたイベントです。同じ名前のイベントは末端に近い状態のものが上書きします。アクターを指定した探索・再生では、そのアクターが起こせるイベントだけを使います。
- 行き先: `to`を持つ遷移は状態へ入り、複合状態なら開始をたどって末端状態へ進みます。開始がディシジョンを持つ場合はそのディシジョンで止まります。`decision`を持つ遷移はディシジョンの構成へ進みます。行き先を持たない遷移は、イベントを起こした末端状態へ戻ります。
- ディシジョン: 分岐は名前だけを持ち、選択は探索では全分岐、シナリオでは手順の分岐名で決まります。分岐の入れ子は木で、合流や循環はありません。

シナリオと探索は同じengineの振り分けと行き先の規則を使います。シナリオの手順はイベント名と分岐名の並びで、engineは遷移IDの列へ変換して再生します。

## 検査と表示

ユースケースパッケージは共通モデルの分類情報です。ユースケースは一つのパッケージまたはルートに属し、パッケージは親を指定してネストできます。コンパイラーは参照と循環を検証し、表示はパッケージ・ユースケース・シナリオの順に配置します。実行エンジンと網羅率はパッケージによって範囲を変えません。変更影響には所属パッケージとその祖先を含めます。

analysisはルート状態の開始から全アクターで制御グラフを探索し、到達できない状態と、到達できる状態から一度も起きない遷移を警告します。ユースケースごとに、`starts`から、ユースケースのアクターが起こせる`scope`のイベント（とその分岐、通過する開始の分岐）だけで制御グラフを探索します。`ends`の遷移を通り、ディシジョンを抜けて末端状態に戻った構成を完了とし、各開始から完了へ到達できるかを検査します。網羅率はこのグラフとシナリオの経路から計算します。構成数や経路探索の作業量が`limits.paths`に達した場合は解析未完了とし、証明に成功したとは扱いません。

検査器はelk-go、HTML、画面座標を知りません。reportは結果を読むだけで、網羅率を再計算しません。全体図は共通モデル、目的別図はscopeから生成します。reportは図ごとに表示集合を作り、表示集合に含める遷移だけをレイアウト入力へ渡します。通常図は`defaultVisible:true`のイベントとその分岐、シナリオ・未網羅候補の選択時はそれに選択経路を加えた遷移、全遷移表示時は全遷移を表示集合とします。表示集合が変わると、elk-goが状態の位置、枠高さ、図幅を再計算します。図の全体図・ユースケース図・複合状態の内部図は、共通の`elk.algorithm=layered`、`elk.direction=DOWN`、`elk.layered.nodePlacement.strategy=NETWORK_SIMPLEX`で自動配置します。状態の任意属性`layoutLayer`は同じ親内の配置順だけを指定し、非負整数の小さい値ほど上、同じ値は同じ配置帯になります。未指定の状態とディシジョンは自動層です。表示集合の変更は描画の入力だけに作用し、共通モデル、ユースケースのscope、制御グラフ、網羅率は保持します。

図では、ディシジョンをそれを持つ遷移の矢印が入る菱形として描きます。イベントのディシジョンはイベントを書いた状態の親の枠内に、開始のディシジョンはその複合状態の枠内に置きます。行き先を持たないイベントは状態枠内の行として描き、自己ループの矢印は付けません。行き先を持たない分岐はイベントの状態へ戻る矢印で描きます。複合状態の開始は枠内の黒丸から描き、開始のディシジョンも描画に含めます。状態の`screen`は状態名と異なるときだけ表示します。

外側開始記号は、全体図ではルート状態の開始の行き先、目的別図ではusecase.startsを指し、各図の最上段・左右中央に固定します。複数の開始状態がある場合は開始記号の列全体を中央に並べます（個々の記号は重ねません）。状態・ディシジョン・遷移はelk-goの自動配置で扱い、固定するのは外側開始記号だけです。開始矢印は固定した開始記号から各開始状態へ接続するよう、reportが接続点を調整します。開始記号とその矢印は表示専用で、検査用モデルの状態・遷移には追加しません。

層指定のある複合状態では、reportが同じ親の隣接する指定層同士へ表示専用の配置制約edgeを渡し、`priority.direction`を1000に設定して層の順序を維持します。このedgeも含めてelk-goが座標と経路を計算しますが、SVGへは出力せず、検査モデルの遷移・遷移ID・網羅率にも追加しません。

`commonRules`はIDから`{name,description}`へのmapで、DBなどのシステムエラーや進捗表示の共通方針を記述します。HTMLに表示するための文章であり、検査は共通メッセージの表示、編集入力の保持、更新・削除の原子的な確定など、システムエラー処理の実装を保証しません。

report.jsonにはモデルハッシュ、版、検査上限、各定義（アクター、状態、遷移、ディシジョン、ユースケースなど）のハッシュ、依存関係、診断、経路を記録します。日時を入れないため同じ入力/版/設定で結果が安定します。エラー診断はファイル名+JSON Pointerを基本とします。

シナリオは利用者目的（goal）と人が読む期待結果（expectedOutcome）を持ちます。自然言語の意図は結果へ伝播しますが、実行エンジンがその意味を検証するわけではありません。

未網羅項目の評価はユースケースのcoverageReviewsに保存し、解析結果の指標ごとの項目IDと照合します。複数の項目を同じ理由・設計要求でまとめられます。評価結果は網羅率の計算後に付加し、分母・分子・閾値・解析完了性から独立させます。評価時の文脈ハッシュと現在のハッシュを比較して古い記録を示します。ハッシュは全体の共有モデル・検査・プロジェクト設定と対象ユースケース・ツール版に依存し、評価記録自身は含みません。変更影響と同様、意味上の再確認の必要性は開発者が判断します。

SVGは表示集合ごとにCLI生成時の実際のelk-goへ入力し、そのJSON出力から独自生成してHTMLへ埋め込みます。文字幅は埋め込みフォントなしの概算です。図は名前と遷移ラベルを簡潔に表示し、クリックすると遷移IDとアクションの詳細を読めます。ブラウザーは埋め込み済みの表示集合別SVGを切り替えるだけで、外部資産の読込・探索・自動レイアウトを行いません。

## 初期化と更新

initは計画を作成し全件照合してから新規ファイルだけを排他的に作成します。異なる内容のある既存ファイルは上書きしません。初期化テンプレートとガイドはCLIにembedします。

単独CLIの更新は同じディレクトリにステージし、旧版を.previousへ移動してから配置します。失敗時は復元を試みます。プロジェクト更新は新しい版のディレクトリを作成してからpinを書き換えます。既存版は保持します。電源断時の完全なアトミック性は保証しません。

## 配布

Windows amd64、CGO_ENABLED=0、単一exeです。GoReleaserを必須にせず、Windows向けPowerShellビルド/梱包スクリプトとGitHub ActionsでReleaseを作ります。初版をWindows限定にしたため、配布方式を一つに絞っています。共通ファイル資産、JSON Schema、HTML/CSS/JSはGo embedで同梱します。

プラグイン、サーバー、外部DB、AI API、バイナリの自動最新版追随はありません。依存はgo.modで版を指定し、ネットワークのある環境で最初にgo.sumを確定してコミットします。
