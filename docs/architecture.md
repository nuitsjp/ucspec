# アーキテクチャ

## 所有と依存方向

共通ツールは独立したGoモジュール/CLIです。各プロダクトは構造化仕様と使用版を所有します。コードはコピーせず実行ファイルを配布します。

```text
cmd/ucspec
  └─ app                 CLI・ファイル出力・終了コード
      ├─ compiler        JSON/YAML読込・形式検証・参照解決
      ├─ engine          式評価・状態更新・シナリオ再生
      ├─ analysis        実行グラフ・網羅率・性質・差分
      ├─ report          レイアウト要求・SVG・HTML
      ├─ project         初期化・テンプレート配置
      └─ update          Release確認・検証・版固定更新

model                     外部ライブラリを知らない共通型
adapters                  YAML / JSON Schema / elk-goとの接続
assets                    embedされた仕様形式・ガイド・閲覧資産
```

mainだけがproductionのCodecとLayoutを組み立てます。coreテストではCodecにJSONを、reportの単体テストではレイアウト契約用fixtureを注入します。fixtureは製品機能のELK代替ではありません。productionで外部依存に失敗しても、黙って簡易レイアウトへ切り替えません。

## パイプライン

仕様読込 → schema検証 → ID参照解決 → 共通内部モデル → 有限実行グラフ/シナリオ再生 → 検査結果 → elk-go配置 → SVG/HTML。Documentのルートにある`commonRules`は共通内部モデルの説明資産として保持し、HTMLの「共通ルール」へ表示します。

実行状態は一つの有効な末端状態IDと有限変数の組です。末端状態の親をたどった複合状態も有効です。UI画面IDだけにまとめて探索しません。statesのparentで包含関係、複合状態のinitialで直接の初期子状態を定義します。複合状態へ入るとinitialを再帰的にたどって末端状態へ進み、同じ規則を初期構成・遷移先・シナリオ再生に使います。並行領域、履歴状態、入場・退場アクション、無限コンテキストは対象外です。モデルのイベントには発生元を持たせますが、イベントキューの並行スケジューリングやネットワーク実装はモデル化していません。

遷移の`kind`は省略時または`external`を外部遷移、`internal`を内部遷移として扱います。内部遷移は`from`と`to`に同じ通常stateを必須とし、choiceを端点にできません。イベント、ガード、アクション、`set`を通常どおり実行しますが、実行構成のアクティブな末端状態は保持します。親stateを端点にした内部遷移でも子stateを維持し、退場・再入場やinitialへの入り直しは行いません。外部遷移の自己遷移は従来どおり対象へ入り直し、複合stateならinitialをたどります。

選択疑似状態は`choices`のID→`{label,parent?}`で定義し、通常の`states`とは別に扱います。parentは既存の複合状態だけを参照できます。stateとchoiceは同じID名前空間を使い、choiceは初期構成・ユースケース開始点・シナリオ開始点になりません。choiceへ入る遷移の`set`を適用した後、choiceから出る分岐のガードを評価します。分岐は既存のtransitionとして`from`にchoiceを指定し、eventを持たず、guardを必須にします。到達構成で同じchoiceのガードが重複成立またはすべて不成立になる場合は有限モデル検査で失敗し、暗黙のelseや任意イベントなし通常状態遷移は作りません。choiceからchoiceへの鎖は許しますが、循環は入力検証で拒否します。

シナリオと探索は同じengine.Applyを利用します。全更新は遷移前の値を読みます。イベントは末端状態とその親から継承します。遷移は末端状態から親へ順に候補のガードを評価し、有効な候補がある最も内側の状態を採用します。同じ状態に有効な候補が複数あれば競合です。採用済みの子状態より外側のガードは評価しません。choiceの分岐も同じ有限実行に含め、分岐には外部イベントを与えません。choiceの選択は内部の実行ステップとして明示し、choice中間ノードでは終了条件・`properties`を成立させず、通常状態へ戻った安定構成で評価します。条件網羅に使うのは実際に評価した候補の論理値です。

## 検査と表示

ユースケースパッケージは共通モデルの分類情報です。ユースケースは一つのパッケージまたはルートに属し、パッケージは親を指定してネストできます。コンパイラーは参照と循環を検証し、表示はパッケージ・ユースケース・シナリオの順に配置します。実行エンジンと網羅率はパッケージによって範囲を変えません。変更影響には所属パッケージとその祖先を含めます。

検査器はelk-go、HTML、画面座標を知りません。reportは結果を読むだけで、網羅率を再計算しません。全体図は共通モデル、目的別図はscopeから生成します。単に画面ノードをまとめた可視化を、検査用グラフとして使いません。reportは図ごとに表示集合を作り、表示集合に含める遷移だけをレイアウト入力へ渡します。通常図は`defaultVisible:true`の遷移、シナリオ・未網羅候補・反例の選択時はそれに選択経路を加えた遷移、全遷移表示時は全遷移を表示集合とします。表示集合に含まれない遷移は配置から除外し、通常図では非表示の内部遷移行を複合stateの枠高さにも含めません。そのため表示集合が変わると、elk-goが状態の位置、枠高さ、図幅を再計算します。図の全体図・ユースケース図・複合stateの内部図は、共通の`elk.algorithm=layered`、`elk.direction=DOWN`、`elk.layered.nodePlacement.strategy=NETWORK_SIMPLEX`で自動配置します。この設定は図全体へ共通に適用し、個別状態の配置属性は追加しません。状態の任意属性`layoutLayer`は同じ親内の配置順だけを指定し、非負整数の小さい値ほど上、同じ値は同じ配置帯になります。異なる値の順序は保証しますが、同じ値の帯内の上下・横配置は自動で、同じY座標や横一列は保証しません。未指定の状態とchoiceは自動層です。表示集合の変更は描画の入力だけに作用し、状態・choiceを含む共通モデル、ユースケースのscope、実行グラフ、網羅率は保持します。

`transition.defaultVisible`は外部・内部を問わず、検査の入力ではなく図の表示集合を決める属性です。`true`は通常図へ含め、未指定または`false`は通常図から除外します。シナリオ・未網羅候補・反例で選択した経路は`defaultVisible`の値に関係なく通常表示の集合へ加え、「全遷移を表示」では全遷移を集合へ含めます。各表示集合を実際のelk-goで配置するため、切替時には状態の位置、複合stateの枠高さ、図幅が変わります。非表示の内部遷移行は通常図の枠高さに含めません。表示集合はレイアウトだけに作用し、実行グラフ、`scope`、網羅率、状態・choiceを含む共通モデルを変えません。

外側開始記号は各図の最上段・左右中央に固定し、複数の開始状態がある場合は開始記号の列全体を中央に並べます（個々の記号は重ねません）。状態・choice・業務遷移はelk-goの自動配置で扱い、固定するのは外側開始記号だけです。開始矢印は固定した開始記号から各開始状態へ接続するよう、reportが接続点を調整します。その他の最上位の状態・ディシジョンをその下へ置きます。複合state内のinitialは包含内の`DOWN`自動配置に任せます。`layoutLayer`はピクセル座標や層の高さを決めず、横位置・間隔・通常の矢印は自動配置に任せます。

層指定のある複合stateでは、reportが同じ親の隣接する指定層同士へ表示専用の配置制約edgeを渡し、`priority.direction`を1000に設定して層の順序を維持します。このedgeも含めてelk-goが座標と経路を計算しますが、SVGへは出力せず、検査モデルの遷移・遷移ID・網羅率にも追加しません。

`commonRules`はIDから`{name,description}`へのmapで、DBなどのシステムエラーや進捗表示の共通方針を記述します。これは有限性質を検査する`properties`とは別の文章であり、HTMLに表示するためのものです。モデル検査は、共通メッセージの表示、編集入力の保持、更新・削除の原子的な確定など、システムエラー処理の実装を保証しません。

状態網羅率は末端状態、複合状態網羅率は有効になった親状態を別々に集計します。遷移の定義IDを保ったまま、外部・内部の遷移を末端状態から実行可能な接続として経路候補へ含め、有限実行グラフで成立性を確認します。内部遷移は状態を移動しない場合でも通常の遷移IDとしてシナリオ、網羅率、経路探索の対象です。子状態ごとに展開された同一遷移を遷移網羅率の分母へ重複加算しません。描画では同じ親子関係をelk-goの包含構造へ渡し、複合状態の枠内に子状態を配置します。

choice自体は通常状態・複合状態の網羅率の分母に含めません。choiceから出る分岐遷移は通常の遷移として扱い、`scope`内の遷移数、連続2遷移、プライムパス、上限付き完了パス、条件、複合条件の分母へ反映します。図ではchoiceをUMLの菱形の中間ノードとして保持し、遷移ラベルは複数行の「イベント [ガード] / アクション」で描画し、位置でイベントとアクションを区別します。イベントはユーザー操作・時間経過・外部処理の応答などの契機、`action`はシステムの振る舞いを表し、ラベルは簡潔な語句で記述します。`source`（`user`/`system`/`timer`）は定義データとして保持し、`user`はユーザー操作、`system`は外部処理の応答、`timer`は時間経過を表しますが、図に「ユーザー：」「システム：」「タイマー：」の接頭辞は表示しません。`guardLabel`は表示用で、判定は`guard`式を使います。`set`は有限変数の更新として表示・追跡します。

図の`choices`と、独立した期待を記す`decisions`は別の概念です。`decisions`は`state`にchoice IDを指定し、`event`を省略してchoice分岐も検査できます。

開始点は全体図ではproject.initial、目的別図ではusecase.startsから取り、黒丸と開始状態への矢印で表示します。同じ制御状態を持つ開始構成は一つの黒丸にまとめ、全体図・ユースケース図の外側では複数の開始状態がある場合も開始記号の列全体を左右中央に並べ、各図の最上段に置きます（個々の記号は重ねません）。開始矢印は黒丸から各開始状態へ接続するよう、reportが接続点を調整します。複合状態の枠内にはinitialへの開始矢印も表示しますが、その位置は包含内の自動配置に任せます。開始記号とその矢印は表示専用で、検査用モデルの状態・遷移には追加しません。

report.jsonにはモデルハッシュ、版、検査上限、各定義のハッシュ、依存関係、診断、反例を記録します。日時を入れないため同じ入力/版/設定で結果が安定します。エラー診断はファイル名+JSON Pointerを基本とします。

シナリオは利用者目的（goal）、人が読む期待結果（expectedOutcome）、モデル上の期待式（expect）を分けて持ちます。自然言語の意図は結果へ伝播しますが、実行エンジンがその意味を検証するわけではありません。

未網羅項目の評価はユースケースのcoverageReviewsに保存し、解析結果の指標ごとの項目IDと照合します。複数の項目を同じ理由・設計要求でまとめられます。評価結果は網羅率の計算後に付加し、分母・分子・閾値・解析完了性から独立させます。評価時の文脈ハッシュと現在のハッシュを比較して古い記録を示します。ハッシュは全体の共有モデル・検査・プロジェクト設定と対象ユースケース・ツール版に依存し、評価記録自身は含みません。変更影響と同様、意味上の再確認の必要性は開発者が判断します。

SVGは表示集合ごとにCLI生成時の実際のelk-goへ入力し、そのJSON出力から独自生成してHTMLへ埋め込みます。文字幅は埋め込みフォントなしの概算です。図はIDと遷移ラベルを簡潔に表示し、クリックするとガード・アクションの詳細を読めます。ブラウザーは埋め込み済みの表示集合別SVGを切り替えるだけで、外部資産の読込・モデル探索・自動レイアウトを行いません。

## 初期化と更新

initは計画を作成し全件照合してから新規ファイルだけを排他的に作成します。異なる内容のある既存ファイルは上書きしません。初期化テンプレートとガイドはCLIにembedします。

単独CLIの更新は同じディレクトリにステージし、旧版を.previousへ移動してから配置します。失敗時は復元を試みます。プロジェクト更新は新しい版のディレクトリを作成してからpinを書き換えます。既存版は保持します。電源断時の完全なアトミック性は保証しません。

## 配布

Windows amd64、CGO_ENABLED=0、単一exeです。GoReleaserを必須にせず、Windows向けPowerShellビルド/梱包スクリプトとGitHub ActionsでReleaseを作ります。初版をWindows限定にしたため、配布方式を一つに絞っています。共通ファイル資産、JSON Schema、HTML/CSS/JSはGo embedで同梱します。

プラグイン、サーバー、外部DB、AI API、バイナリの自動最新版追随はありません。依存はgo.modで版を指定し、ネットワークのある環境で最初にgo.sumを確定してコミットします。
