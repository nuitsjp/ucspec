# ucspec

**利用者の目的を中心に、仕様・シナリオ・網羅性を一緒に育てるためのGo製CLIです。**

顧客との接点を持つ開発者のユースケース駆動開発を支援します。ユーザー目的とシナリオの期待結果を明確にして実装・テストの根拠を作り、未網羅経路に業務上の意味があるかを評価します。E2Eテストの生成・実行・対応付けと、顧客との合意状態の管理はこのツールのスコープ外です。

プロダクト内で一元管理した状態遷移モデルを、複数のユースケースが参照します。人とAIが構造化した仕様を編集し、決定論的な検査器が状態の構造の整合性・シナリオの成立・ユースケースの完了可能性・シナリオの定義網羅率を検査します。仕様はデータを持たず、データの中身と業務の論理は実装とそのテストが受け持ちます。結果を、図とシナリオを行き来できる自己完結型HTMLへ出力します。

**検証状況:** Windows amd64でのコア・実依存を含む全体テスト、go vet、実行中exeの置換、CLIビルドとinit、実際のELKによる階層図生成、ブラウザーテストの履歴を [検証記録](docs/verification.md) に記載しています。各変更時点の実行環境と確認範囲を区別して記録しています。統合コミット `fa336eb` の [Windows CI](https://github.com/nuitsjp/ucspec/actions/runs/38176522541) は成功しています。実Releaseからの更新は未確認です。

## 目的と設計原則

- 開発はユースケースの目的から始める。画面遷移図を先に完成させて分解する方式ではありません。
- 同じ画面・状態・イベントをユースケースごとにコピーしない。共有する論理画面は一度だけ定義します。
- 図、シナリオ表、網羅率は正本データから生成します。生成HTMLを直接編集しません。
- 意図した振る舞い・禁止事項・期待結果はモデルと独立に記述します。AIが候補を自動承認する方式ではありません。
- AIは編集を支援しますが、検査・生成の実行にAIサービスは必要ありません。

## 機能

| 分類 | 実装 |
|---|---|
| プロダクト導入 | `init`、dry-run、既存ファイル保護、ローカル版固定、PowerShellランチャー |
| 仕様の正本 | JSON / YAML、JSON Schema、名前による参照、アクター、入れ子の状態と開始、状態に書くイベント（親からの継承と上書き）、名前付き分岐のディシジョン、ネスト可能なユースケースパッケージ |
| シナリオ検査 | イベントと分岐名の手順、アクターの権限、`scope`、ユースケースの終了 |
| シナリオの意図 | 必須の目的・人が読む期待結果を操作列より先に表示 |
| 未網羅の評価 | 追加シナリオ・既存シナリオでの代表・禁止の判断、理由、設計要求。網羅率と分離し変更後は再評価候補を表示 |
| Agent Skill | プロジェクト内のスキルを同梱し、init先にも配置 |
| 網羅率 | 末端状態、複合状態、遷移（イベントと分岐）、連続2遷移、プライムパス、上限付き完了パス |
| 構造検査 | 名前と参照、開始、ディシジョン、ユースケースの完了可能性、到達できない状態・遷移の警告 |
| 回帰・変更影響 | ユースケース横断の回帰、アクターが起こせない操作の拒否、過去のreport.jsonとの差分 |
| 仕様書 | elk-goで配置したSVG、全体/ユースケース別図・複合状態の内部図、シナリオ・未網羅経路の強調 |
| 更新 | GitHub Releases、明示更新、SHA-256、Windows PE/版確認、旧版保持、プロダクトの横並び更新 |

`verified` は「モデルと設定された検査に合格」の意味です。すべての網羅率100%や実装のテスト完了を意味しません。

## 最初に動かす

### このソースZIPから

Windows amd64、PowerShell、Go 1.23以上、Goモジュールを取得できるネットワークが必要です。配布済み実行ファイルを使う側にはGo・Node.jsは不要です。

```powershell
# リポジトリのルートで実行。依存復元→総合テスト→Windowsビルド
.\scripts\build.ps1

# 同梱サンプルの検査・HTML生成
.\dist\ucspec.exe build --project examples/customer-crud/spec/project.json
Start-Process .\examples\customer-crud\artifacts\ucspec\index.html

# サンプルの実際のUI（サーバー不要の参考アプリ）
Start-Process .\examples\customer-crud\app\index.html
```

同梱サンプルは顧客管理システムです。内容と操作は [examples/customer-crud](examples/customer-crud/README.md) を参照してください。

図のイベントは`defaultVisible`で通常表示を指定します。未指定または`false`は通常非表示です。通常図では`true`のイベントとその分岐だけを表示集合として配置し、シナリオ・未網羅候補を選択したときはそれに選択経路を加えて配置します。「全遷移を表示」では全遷移を配置します。表示集合が変わるとelk-goの再配置により状態の位置、複合状態の枠高さ、図幅も変わります。状態に留まるイベントの非表示の行は通常図の枠高さに含めません。CLI生成時に表示集合ごとのSVGを実際のelk-goで生成してHTMLへ埋め込み、ブラウザーは生成済み図を切り替えます。表示集合の選択は描画だけに関わり、共通モデル、ユースケースの`scope`、検査や網羅率は変えません。

全体図、ユースケース別図、複合状態の枠内は、共通のELK設定で上から下（`DOWN`）へ自動配置し、`NETWORK_SIMPLEX`をノード配置方式に使います。状態の任意属性`layoutLayer`は同じ親の中での配置順だけを指定し、非負整数の小さい層を上に、同じ層を同じ配置帯にします。異なる層の順序は保証され、同じ層の帯内の上下・横配置は自動です。同じY座標や横一列は保証しません。未指定の状態とディシジョンは自動配置に任せます。全体図とユースケース別図の外側開始を示す黒丸は各図の最上段・左右中央に固定し、複数の開始状態がある場合は開始記号の列全体を中央に並べます（個々の記号は重ねません）。それ以外の最上位の状態・ディシジョンをその下に配置します。複合状態の枠内にある開始の黒丸、横位置、間隔、矢印は自動です。`layoutLayer`はピクセル位置や層の高さを指定するものではありません。

Documentのルートに置く`commonRules`は、DBなどのシステムエラーや進捗表示を共通ルールとしてHTMLの「共通ルール」へ表示するための文章です。検査はシステムエラー処理の実装を保証しません。

### 自分のプロダクトへ導入

```powershell
.\dist\ucspec.exe init --dir C:\work\product-a --name Product-A --dry-run
.\dist\ucspec.exe init --dir C:\work\product-a --name Product-A
Set-Location C:\work\product-a
.\scripts\ucspec.ps1 build
```

`init` はモデル・ユースケース・回帰・記述ガイド・利用ガイド・スキーマ・版固定・ランチャーを生成し、実行中のCLIを `.tools/ucspec/<version>/` にコピーします。既存の異なる内容を上書きしません。

仕様をAIと編集する際は、プロジェクト用の [ucspec-authoringスキル](.agents/skills/ucspec-authoring/SKILL.md) を使えます。`init` 先にも `.agents/skills/ucspec-authoring/SKILL.md` を配置します。シナリオの目的・期待結果、指標ごとの未網羅評価、再試行などを代表させる前提からの設計要求の抽出を支援します。

## 使い始める順序

1. [オンボーディング](docs/onboarding.md)でサンプルを確認する。
2. [利用者マニュアル](docs/user-manual.md)で初期化・生成・更新の操作を確認する。
3. [状態定義モデル](docs/model.html)で要素の関係をつかみ、[記述ガイド](docs/authoring.md)を参照して、最初のユースケースからモデルを置き換える。
4. 検査結果を読み、[網羅率と保証範囲](docs/coverage.md)を理解してからCIの閾値を決める。

設計と開発: [アーキテクチャ](docs/architecture.md) / [貢献・テスト](CONTRIBUTING.md) / [リリース](docs/releasing.md) / [セキュリティ](SECURITY.md)。

## GitHubへの初回登録

```powershell
# Git、認証済みGitHub CLI、Goが必要。初期値はprivate。既存repoは変更しません。
.\scripts\publish-github.ps1 -Repository nuitsjp/ucspec
```

このスクリプトはソースを検査し、依存ロックを作成してから新規リポジトリを作成・初回pushします。公開したい場合だけ `-Visibility public` を指定します。タグとReleaseは別の明示操作です。

## 対象外

実アプリのE2Eテスト、データの中身と業務の論理の検証、必然的終了の証明、並行領域、履歴状態、入場・退場アクション、画面編集GUI、DB、サーバー、定期的な自動更新は初版の対象外です。ブラウザーに表示する図は検査結果のビューであり、グラフ配置を検証に逆利用しません。
